Regression · deployed app

Used car price prediction

XGBoost pipeline with a Streamlit app. Enter what you know about a car; fields you tick as unknown are filled from training defaults. It returns a price and an empirical 90% interval taken from held-out residuals, not a made-up percentage.

R² on held-out test data, 300,000-row cleaned sample
Engineering details
  • XGBoost: RMSE $4,412, MAE $2,514, R² 0.949.
  • Hierarchical target encoding for model names: unseen model falls back to its manufacturer, then to the global mean.
  • "Known" checkbox on all 22 inputs, plus a count of how many fields informed the estimate.

ROC curves · 16% leave
Classification · business framing

Employee attrition prediction

Predicts who is likely to leave from an HR record (IBM HR Analytics, 1,470 employees) and serves it in a Streamlit UI. The metric choice is the interesting part: with about 84/16 class imbalance, accuracy lies, so I selected on ROC-AUC and recall.

ModelAccRecallAUC
Logistic Regression0.7550.6170.798
Random Forest0.8370.4890.785
XGBoost0.8500.1910.789
Why the "worse" model won
  • XGBoost has the best accuracy but catches only 19% of real leavers.
  • Logistic Regression catches 62%. For an HR team, a missed leaver costs more than a false alarm.
  • Three engineered features: tenure ratio, income per year, promotion gap.

Hotel booking cancellations

A full audit-and-clean pass over 119,390 bookings: missing-value strategy, duplicate removal, 3x IQR outlier filtering, and engineered stay-length and guest-count features. Repo includes a Gradio demo app.

// how I workThe habits behind the numbers

Honest evaluation

Pick the metric that matches the cost of a mistake. Report the model that fits the problem, even when another one has higher accuracy.

Reproducible by default

Stratified, seeded splits. Preprocessing and model saved as one pipeline so test data cannot leak. MLflow runs for every experiment.

Team engineering

Pull requests, review before merge, tests alongside the code, and a repo layout other people can pick up without asking me.

Say what is not done

READMEs list open work and unverified numbers plainly. Fewer surprises for whoever reads the project next.
